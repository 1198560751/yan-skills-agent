# Rankup 项目记忆协议

本文件定义网站项目内 `.rankup/` 的结构、初始化模板和读写规则。它保存项目事实、决策、证据与经验，使后续执行者可以先恢复上下文，再继续建设和增长工作。

## 目录结构

保持以下路径和职责稳定：

```text
.rankup/
├── INDEX.md
├── PROJECT.md
├── architecture.md
├── infrastructure.md
├── integrations.md
├── secrets.md
├── skill-state.json
├── baseline.md
├── keywords.md
├── decisions.md
├── audit.md
├── plan.md
├── roadmap.md
├── iterations.md
├── experiments.md
├── releases.md
├── experience.md
├── scripts/
├── journal/
└── topics/
```

- `INDEX.md`：目录导航、读取建议、文件状态和最近更新。
- `PROJECT.md`：目标用户、定位、商业模式、目标与非目标。
- `architecture.md`：应用、包、数据模型和服务边界。
- `infrastructure.md`：Cloudflare 环境、非敏感资源标识、bindings 和域名。
- `integrations.md`：支付、邮件、分析、搜索平台等集成状态。
- `secrets.md`：只保存密钥元数据，绝不保存真实值。
- `skill-state.json`：本地 Skill 版本、启用时间和更新检查状态；由版本检查脚本维护。
- `baseline.md`：技术、SEO、流量、转化、收入和成本基线。
- `keywords.md`：关键词证据、聚类、页面映射和复查日期。
- `decisions.md`：重要决策、备选方案、依据和影响。
- `audit.md`：问题、证据、严重度、状态和复验结果。
- `plan.md`：当前优先级、负责人、状态和验收标准。
- `roadmap.md`：长期方向与阶段目标。每个阶段写清进入条件、判定条件与放弃条件，跨会话可续，不随单轮任务改写。
- `iterations.md`：每轮迭代一段——做了什么、判据、结果、下一轮唯一改进。失败轮次必须记录并写明被证伪的假设，否则同一个错误会被重复执行。
- `experience.md`：本项目可复用结论的完整原文，保留证据出处与具体数字。通用规则可回流 Skill，证据留在这里。
  **每条必须以 `- **[YYYY-MM-DD] 标题**` 起头**，正文缩进两格接在下面：

  ```markdown
  - **[2026-01-15] 一句话说清这条结论**

    正文。保留数字与证据出处。
  ```

  这不是排版偏好，是 `scripts/review.mjs` 的**切分依据**。用 `## 标题` 分条会让它读出
  「条目总数：0」，于是重复检测与回流候选**从建库起就没工作过**，而报告看起来一切正常。
  这是本协议里最容易发生的静默失效，实测踩到过一次：一个已积累 12 条结论的库长期被报成 0 条。
- `scripts/`：可复用操作脚本，尤其是浏览器操作。
- `experiments.md`：假设、变更、指标、时间窗和结论。
- `releases.md`：发布版本、环境、验证、监控和回滚信息。
- `journal/`：按日期保存开发、运营、排障和增长日志。
- `topics/`：经过整理、可在本项目复用的专题经验。

## 每次任务的读取顺序

1. 读取 `.rankup/INDEX.md`，确认项目地图、最近变化和相关文件。
2. 读取 `.rankup/skill-state.json`，确认 Rankup 版本和更新检查状态。
3. 读取 `.rankup/PROJECT.md`，恢复目标、约束和非目标。
4. 只读取当前任务需要的专题文件；不要无差别加载整个目录。
5. 在采取行动前，把记录与当前代码、Git 历史和适用的线上提供方重新核对。

记录是上下文，不是永远正确的事实。涉及部署、资源、索引、支付或外部账户时，必须按任务范围核对代码与 Git，并检查 Cloudflare、GSC、Stripe 或其他实际系统。无法访问某个系统时，明确标记“未实时验证”，不要把旧记录描述为当前状态。

## `secrets.md` 安全契约

`secrets.md` 只能使用以下八列，列名和顺序保持一致：

```markdown
# 密钥登记

| name | purpose | environment | provider/storage location | owner | access status | rotated at | next rotation |
|---|---|---|---|---|---|---|---|
| <非敏感名称> | <用途> | preview/staging/production | <Worker Secrets、Secrets Store、CI 或提供方控制台> | <负责人或团队> | available/restricted/rotation-needed | <日期或 never> | <日期或待定> |
```

即使 `.rankup/` 没有提交 Git，也禁止写入：

- 密钥真实值或可以还原真实值的片段；
- 访问令牌、会话令牌、OAuth 凭据和授权头；
- 私钥、助记词、证书私钥和签名材料；
- Webhook 签名密钥；
- 密码、恢复码和一次性验证码；
- 完整支付卡信息、银行信息或其他支付敏感数据；
- 不必要的个人身份信息、联系方式或可识别用户的数据；
- 生产数据样本、日志或命令输出中夹带的上述内容。

真实值只进入 Cloudflare Worker Secrets、Cloudflare Secrets Store、Stripe Dashboard、受控 CI secrets 或用户明确选择的密钥管理系统。命令输出和测试夹具也不得包含真实值。发现泄漏时停止传播，按提供方流程撤销或轮换，并只在项目记忆中记录事件、影响和轮换状态。

## 写入与一致性规则

- 只记录经过观察或验证的事实；推测必须标记为“假设”并附复查条件。
- 每次实质变更都更新最小必要文件，并给记录加日期、证据和关联路径。
- 外部状态变化时，搜索并更新所有过时交叉引用，而不只修改首次发现的文件。例如生产域名、Worker 名称、D1 migration、Stripe 模式、发布 SHA 或索引状态变化后，同时检查 `INDEX.md`、`infrastructure.md`、`integrations.md`、`plan.md`、`releases.md`、相关日志和主题文件。
- 把被取代的决定标记为 `superseded`，保留历史依据，不静默改写过去。
- `INDEX.md` 的文件状态和“最近变化”必须与本次写入同步。
- 日志是时间线，主题文件是当前整理后的知识；定期把稳定结论提升到 `topics/`，并在日志保留来源链接。
- 只有经多次验证、与具体项目无关且可跨项目复用的经验，才候选回流 Rankup Skill；项目秘密、账户标识和用户数据永不回流。回流时只带走剥离站点后仍成立的规则，站名、域名、流量数字与证据出处留在 `experience.md`。

## 沉淀义务

写回 `.rankup/` 的义务只取决于项目里有没有这个目录，与本轮是否调用了 Rankup Skill 无关。

- 该项目中**任何**任务完成后都要沉淀，不限于 SEO——功能开发、重构、排障、发版、依赖升级同样适用。
- 判据是“下次遇到同类问题能否少走一遍”。能，就写；不能，就不写，避免堆流水账。
- 用户没有显式要求也要写。写完在回复里提一句写了什么即可，不必请示。
- 长期方向进 `roadmap.md`，单轮结果进 `iterations.md`，可复用结论进 `experience.md`，一次性排障过程进 `journal/`。

## 三层归属

| 层 | 位置 | 放什么 | 进 Git 吗 |
|---|---|---|---|
| Skill | 本 Skill 仓库 | 剥离站点后仍成立的通用方法与规则 | 是，且开源 |
| 项目 | `<project>/.rankup/` | 本站的事实、数字、裁决、脚本、登录态与凭据存放位置 | 进该项目仓库 |
| 本机 | Skill 目录下的 `registry.md` | 跨项目资产索引（项目名、路径、脚本清单） | **否**，gitignore + 构建断言双保险 |

登记表由 `rankup/scripts/registry.mjs scan` 扫描生成，不手工维护。它含项目名与绝对路径，
描述的是这台机器上项目之间的关系，因此文件虽然放在 Skill 目录里，却绝不进 Git：
`rankup/.gitignore` 排除它，`validate-rankup.mjs` 再断言它未被追踪，`git add -f` 也会当场构建失败。

## 可复用操作脚本

任何需要第二次执行的操作，第一次跑通时就固化成脚本，不允许下次重新摸索。浏览器操作是最主要的适用对象。

- **判定**：满足“会再做一次”或“换个站/换个词就要重跑”即为可复用操作；一次性排查不适用。
- **命名与位置**：`.rankup/scripts/<动词-对象>.mjs`，例如 `gsc-switch-property.mjs`、`gsc-export-queries.mjs`、`serp-top10.mjs`。
- **参数化**：property、日期范围、关键词、国家等一律作为参数，不得写死某一次的具体值。缺参数时报出人话错误，不要静默用默认值。
- **登记**：在 `INDEX.md` 记一行——用途、参数、依赖的登录态、已验证日期。
- **维护**：失败时修脚本，不是绕过它手工再点一遍。页面改版是正常损耗；修完更新已验证日期，并把失败原因写进脚本头部注释。
- **归属**：脚本连同它依赖的登录态、property ID 与账号配置都只属于本目录，永不回流 Skill。
